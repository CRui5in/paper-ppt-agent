# 任务恢复与公式排版（2026-11-02）

## 任务恢复

失败或取消的任务可通过结果页左侧的“继续任务”操作。

- “从断点继续”：复用完成的解析、讲稿、设计方案和页面。已保存但尚未完成处理的原始 SVG 继续进入排版步骤。
- “重试未完成部分”：重新请求未完成页面，保留已完成页面和失败原始输出。
- “保存问题反馈”：单独保存问题、任务状态和错误信息；填写反馈后继续任务时，反馈会传给后续生成步骤。

继续执行会建立关联任务，沿用原工作区和原生成参数。原失败记录保持可查看；同一个工作区同时执行一个继续任务。删除其中一个任务时，其他任务仍引用的工作区会保留。

检查点采用原子写入，记录解析结果、素材、阶段产物和逐页输出哈希。进程重启后可读取。输出文件变化或缺失会明确报错。

旧的 Provider 任务可复用保存的原始请求、讲稿、设计方案和页面；缺少原始请求的任务会显示状态说明，反馈仍可保存。Agent 模式从已有工作区和 SDK 会话继续。

接口：

- `GET /api/generate/{job_id}/recovery`
- `POST /api/generate/{job_id}/resume`，`mode` 为 `resume` 或 `retry_failed`，可带 `feedback`
- `GET/POST /api/generate/{job_id}/feedback`

## 公式排版

原实现使用 Matplotlib Mathtext。扩展检查中的 13 组常见写法有 8 组不兼容，涵盖矩阵、分段、多行对齐、编号、部分分式及操作符写法。

公式现统一使用固定版本 MathJax 4.1.3；预览、几何检查和原生 PPTX 导出使用同一组矢量轮廓。移除了此前为 Mathtext 编写的命令替换。原 `data-latex` 和标题保留。

引擎在本地 Node 进程中复用已加载字体，字形范围从本地依赖加载。每条公式使用独立 TeX 上下文，宏定义和编号互不污染。引擎样式会内联，中文文字使用本机真实字形轮廓，AMS 编号的 SVG 视口会转换为普通路径坐标。

保留明确的公式错误：未定义命令、缺少括号、未闭合环境会报出原始表达式和错误。排版失败不会触发模型自动改写或图片降级。

验证记录：24 组常用 TeX 构造通过排版及原生 PPTX 导出，包含中文、矩阵分隔线、编号、多行、上下标、操作符、宏和颜色；保存任务中 51 条不同公式通过排版。可用 `python -m scripts.audit_math_typesetting workspaces` 重新审计。

前端操作由用户验收，本次只执行后端检查和 TypeScript 编译。
